# 计划清单

### 阶段一：手搓“裸机 RAG”
**目标：** 不用任何 RAG 框架，只用原生 Python 代码跑通全流程。
**怎么干：**
1. **纯手工切片：** 找一篇几千字的文章，自己写 Python 字符串切片代码，按标点符号或换行符把它切成几十个 Chunk。
2. **纯手工向量化：** 直接调 OpenAI 或其他大模型的 Embedding API，把切片变成一堆数字数组。
3. **纯数学检索：** 不用任何向量数据库（如 Milvus、Qdrant），直接用 Python 的 `numpy` 库，手写一个**余弦相似度（Cosine Similarity）**的计算函数，让你的问题向量和所有切片向量做矩阵点乘，找出 Top 3。
4. **纯手工组装：** 把这 Top 3 的文本用 Python 字符串拼接到 Prompt 里，发给大模型。
**价值：** 只要你自己用 `numpy` 算过一次向量距离，你对检索的本质就会有肌肉记忆，以后任何框架的检索模块在你眼里都是透明的。

### 阶段二：直面“脏数据”与高级检索
**目标：** 解决真实企业环境中最让人头疼的数据处理和精度问题。
**怎么干：**
1. **解析深水区：** 不要只用纯文本。找一份带有复杂表格和双栏排版的 PDF，尝试用 PyMuPDF 或者直接调用多模态大模型的视觉能力（VLM）去精准提取里面的信息。
2. **接入真实向量库：** 抛弃 LangChain 的封装，直接去读 Qdrant 或 Milvus 的官方原生 Python SDK 文档，学习怎么建表、怎么给切片打 Metadata（元数据，用于企业权限隔离的过滤）。
3. **手写 Rerank（重排序）：** 在检索之后，加上一步调用 BGE-Reranker 等重排序模型的原生代码，体验精度是如何被强行拉高的。

### 阶段三：手撸路由与自适应
**目标：** 引入逻辑判断，不再无脑检索。
**怎么干：**
自己写一个简单的大模型调用，作为“分类器（Router）”。
用户输入问题 $\rightarrow$ 发给小模型（如 7B 模型）判断 $\rightarrow$ 如果是闲聊，直接返回答案；如果是知识查询，再触发你写好的检索代码。你会发现，所谓的 Adaptive RAG，本质上也就是几个 `if-else` 分支加上精准的 Prompt。

### 阶段四：登顶 Agentic RAG
**目标：** 把前面的能力封装成工具，交给 Agent 自主调用。
**怎么干：**
不用 LangGraph，直接用原生 Python 写一个 `while` 循环。
1. 定义好你的工具列表（比如你前面写好的：图谱检索工具、向量检索工具、Web 搜索工具）。
2. 让大模型输出它的思考过程（Thought）、行动（Action）和参数（Action Input）。
3. 用 Python 拦截它的输出，执行对应的检索工具，把结果（Observation）返回给大模型。
4. 循环这个过程，直到大模型认为信息收集完毕，输出最终答案（Final Answer）。
